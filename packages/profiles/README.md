# RepoSpec 방법론 프로파일 팩

방법론을 코드가 아닌 데이터로 둔다. 프로파일을 바꾸면 산출물 목록, ID 체계,
추적 규칙, 시험 레벨, 게이트, 프롬프트가 통째로 교체되고 엔진 코드는 동일하다.

## 합성 구조

```
최종 프로파일 = _base
              → lifecycle/{v-model | agile}
              → industry/{D01~D18}
              → overlay/{X1~X5}      (조건부 발동, 복수 가능)
              → org                  (조직 포크, 선택)
              → project_override     (프로젝트 단위, 선택)
```

생명주기를 도메인에서 분리한 것이 핵심이다. 공공 사업도 애자일로 수행될 수 있고
자동차에도 하이브리드가 있다. 두 축은 직교한다.

## 합성 규칙

| 필드 | 방식 |
|---|---|
| `standards` | union, 동일 id면 `enforcement` 최댓값 (L1 > L2 > L3 > L4) |
| `artifacts` | union, 동일 id면 후순위 override |
| `quality_gates` | union, 동일 name이면 더 엄격한 threshold |
| `traceability_rules` | union, `required`는 OR |
| `lint_rules` | union, 동일 id면 severity 최댓값 |
| `id_scheme` | 키 단위 last-wins. 오버레이는 변경 금지 |
| `lifecycle` | lifecycle 레이어만 설정 가능 |

원칙은 strictest-wins다. 단일값 필드만 last-wins로 예외 처리한다.

## 규칙 적용은 2단계다

규칙을 만나는 즉시 적용하면 결과가 규칙 순서에 좌우된다. 완화가 필수화보다 먼저
평가되면 충돌 감지 자체가 일어나지 않아, 조직 포크가 규칙을 하나 추가하는 순간
결과가 뒤집힌다. 따라서:

1. **수집** — 전 규칙을 평가해 의도(intent)만 모은다
2. **해소** — 우선순위로 확정한다: `add` > `drop` > `relax`

`add`가 `drop`을 이기는 이유는 규제가 요구한 산출물을 편의 규칙이 지울 수 없기
때문이다. `drop`이 `relax`를 이기는 이유는 적용 범위 밖이라 제거된 산출물이
선택항목으로 남을 이유가 없기 때문이다.

## 조건부 필터링

활성화되지 않은 조건부 산출물·표준은 결과에서 **완전히 제외**된다. 선택항목으로
남기면 작업지시서가 흐려지고, 수출하지 않는 프로젝트의 준거 목록에 21 CFR Part 11이
남아 실제 의무를 반영하지 못한다.

- **산출물**: `conditional: true`로 명시
- **표준**: `risk_trigger`를 선언하고, 어떤 규칙의 `add_standards`에 등장하면
  조건부다. 둘 중 하나만으로는 부족하다. `risk_trigger` 없이 규칙이 추가하는
  표준은 PL-13이 막는다.

제외된 표준은 `deferred_standards`에 이유와 함께 보존된다.

### 강제성은 조건에 따라 움직인다

같은 표준을 한 레이어는 무조건 선언하고 다른 레이어는 조건부로 선언할 수 있다.
이때 조건이 발동하지 않으면 무조건 선언분의 강제성이 적용된다.

```
X2 오버레이  : KISA 개발보안 가이드, L3 (권고), risk_trigger 없음
D01 산업레이어: KISA 개발보안 가이드, L2 (계약 필수), 보안약점 진단 대상일 때

→ 진단 대상 아님: L3로 적용, enforcement_if_triggered = L2
→ 진단 대상:     L2로 적용
```

이를 구분하지 않으면 진단 대상이 아닌 사업의 준거 목록에도 L2가 찍혀
실제 의무가 과장된다.

## 산출물 도출 등급

| 등급 | 정의 | 처리 |
|---|---|---|
| A | 코드에서 결정론적 추출 | 자동 생성 |
| B | LLM 추론, 증거 앵커 필수 | 자동 생성 + 검수 강제 |
| C | 조직·계약·운영 맥락 필요 | **골격만. AI 생성 금지** |

C등급에 생성 프롬프트를 연결하면 `profile-lint` PL-05가 막는다. 이를 허용하면
AI가 시험 결과서와 검증 기록을 지어내게 되고, 그 문서가 심사 제출물이 된다.

## 검증

```bash
./tests/run_all.sh
```

| 단계 | 내용 |
|---|---|
| `profile_lint.py` | PL-01~PL-13. 스키마, 순환, 참조 무결성, C등급 프롬프트 금지, 발동조건 선언, 골든셋 유무 |
| `test_lint_rules.py` | 린터 규칙 회귀 9건. 각 PL 규칙이 실제로 위반을 잡는지 |
| `test_conditions.py` | 조건 평가기 12건. 등급 비교 의미, 연산자, 컨텍스트 검증 |
| `test_resolver_guards.py` | 방어 가드 10건. 잘못된 레이어 거부, 합성 이력, 순서 독립성 |
| `run_goldenset.py` | 전 프로파일 조건 분기 28건 (D01 12건, D04 16건) |

`show_resolution.py`는 시나리오별 해소 결과를 표로 비교한다. 통과/실패만으로는
규칙 설계가 의도대로인지 알 수 없어, 실제 산출물·표준 수의 변화를 눈으로 본다.
조건부 표준 누락 결함은 이 표를 보다가 발견됐다.

변이 테스트로 검증 강도를 확인했다. 17개 변이 전부 검출된다.
새 규칙을 추가할 때는 골든셋 케이스를 함께 넣고, 해당 로직을 의도적으로
망가뜨려 테스트가 실패하는지 확인하라. 통과만으로는 검증되었다고 할 수 없다.

## 새 프로파일 추가 절차

1. `industry/<코드>-<이름>/profile.yaml` 작성, `status: draft`
2. `context_schema`에 선택 규칙이 참조할 변수를 전부 선언
3. `selection_rules` 작성 — `if`의 모든 변수는 `context_schema`에 있어야 한다
4. `evals/goldenset.yaml`에 조건 분기 케이스 작성
5. `./tests/run_all.sh` 통과 후 `status: beta`
6. 기준 저장소로 추출 케이스까지 검증한 뒤 `status: stable`

골든셋 없이 `stable`로 올리면 PL-09가 막는다.

## D01 공공 프로파일 — 추적축이 둘이다

| | 요구사항추적표 (AN-03) | 과업대비표 (AU-01) |
|---|---|---|
| 목적 | 내부 추적 | 계약 이행 증명 |
| 축 | 요구사항 → 설계 → 시험 | RFP 요구사항 → 산출물 |
| 독자 | 개발팀 | 감리원, 발주기관 |
| 질문 | "이 요구가 어디서 구현되고 검증됐나" | "발주한 과업이 전부 이행됐나" |

둘을 하나로 합치면 감리에서 과업 누락 소명이 불가능해진다. 과업대비표는
RFP 요구사항을 사용자가 제공해야 만들 수 있으며, 코드에서 복원한 요구사항으로
대체할 수 없다. 복원된 요구사항은 "구현된 것"이지 "발주된 것"이 아니다.

PMR(프로젝트관리)·PSR(프로젝트지원) 계열은 코드에 흔적이 없으므로 생성하지
않는다. 억지로 도출하면 감리에서 근거 없는 요구사항으로 지적된다.

## HWPX 출력 — 검증된 것과 아닌 것

`services/docgen/render_hwpx.py`가 `python-hwpx`로 OWPML을 직접 생성한다.

| 검증됨 | 검증 안 됨 |
|---|---|
| ZIP 무결성, XML 적합성 | 한글에서의 실제 열람 |
| mimetype (`application/hwp+zip`) | 서식·여백·글꼴의 납품 적합성 |
| 한글 텍스트·표 구조 삽입 | 감리 제출 시 수용 여부 |

LibreOffice에는 HWPX 임포트 필터가 없어 이 환경에서 교차 검증이 불가능하다.
**실제 납품 전 한글 실물 검수가 반드시 필요하다.** 첫 고객 건에서는 DOCX를
병행 제출해 위험을 낮추는 것이 안전하다.

## 주의

표준 원문은 저작권 보호 대상이다. 템플릿과 룰셋에 ISO/IEC/IEEE 원문 텍스트를
넣지 않는다. 조항 번호 참조와 자체 작성 체크리스트만 사용한다.

"ISO 29148 준거"와 "ISO 29148 인증"은 다르다. 인증 주장을 하지 않는다.
